# git_ops - ניהול git בפרויקט

מודול: git_ops | פרויקט: protomotai | גרסה: 0.2 | סטטוס: טיוטה | מצב: דלוק | תלוי ב: core | רמת סיכון: בינונית | עודכן: 2026-10-23 | עודכן על ידי: claude

- ריפו אחד לפרויקט; לעולם לא פעולות git בריפו של פרויקט אחר. אין remote ו-push בלי אישור.
- זהות מקומית בלבד (`git config user.name/user.email` בריפו). הודעות commit באנגלית. שורות השיוך (Co-Authored-By, Claude-Session) לפי הוראת המערכת.
- בלי git בפרויקט: נוהל נקודת חזרה בהעתקה ב-`core §12.14`.
- commit לכל שלב לוגי; הודעה: שורת תקציר + גוף קצר. tag לנקודת חזרה לפי `filename_templates.md`.
- אסור `--no-verify`, `git reset --hard` או כתיבה מחדש של היסטוריה בלי אישור.

## בתיקייה מחוברת בלי הרשאת מחיקה (נלמד בפועל)
git מוחק קבצי נעילה וזמניים בעצמו; בלי הרשאת מחיקה נשארים `.git/HEAD.lock` ו-`.git/objects/maintenance.lock` והפקודה הבאה נכשלת.
פתרון בלי מחיקה, **רק לנעילה שאומתה כישנה** (אין תהליך git פעיל: `pgrep -a git` ריק, וגיל הקובץ מעל דקה) ורק בסביבה שבה אין הרשאת מחיקה: להעביר את הנעילה הישנה לשם חדש (לא מתחת ל-`refs`): `mkdir -p .git/stale_locks; mv .git/HEAD.lock .git/stale_locks/<epoch>_HEAD.lock`. קבצי `tmp_obj_*` לא מפריעים.
העבירו רק נעילה שנשארה מפקודה קודמת שלכם, לעולם לא נעילה של git שרץ כרגע.
הרשאת מחיקה ניתנת רק לתיקיית שורש מחוברת שלמה; אם השורש מכיל פרויקטים אחרים אין לבקש אותה.

## תוספות v0.3
- tag לנקודת חזרה לפני כל ריצה (`pre-<subject>-s<step>-<yyyymmdd>`).
- כשמודול החלטות אוטומטיות דלוק: commit נפרד לכל החלטה אוטומטית (ביטול ב-`git revert`). נקודת שחזור שמבוססת על tag מבטלת גם עבודה לא קשורה, ולכן לא משתמשים בה לבדה.
- אחרי כל פקודת git בתיקייה מחוברת, **אם נותרה נעילה שאומתה כישנה** (ראה למעלה): להעביר אותה (כולל `.git/objects/maintenance.lock`) ל-`.git/stale_locks`. הנוהל תלוי בסביבה ואינו חל כשיש הרשאת מחיקה.
