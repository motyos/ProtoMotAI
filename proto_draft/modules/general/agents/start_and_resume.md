# start_and_resume - נקודת פתיחה, נקודת חזרה ותיעוד תוך כדי ריצה

## עיקרון
הקשר הצ'אט נדחס ואובד. **הקבצים הם מקור האמת** להמשך עבודה, לא זיכרון הצ'אט. (בניסיון קודם נוסח התוכנית המאושרת אבד בדחיסה ושוחזר מהמפרט עם סימון "משוחזר".)

## נקודת פתיחה
1. גישה לשרת ולתיקיות (אם אין: לא עונים על מצב הפרויקט, מבקשים לקשר).
2. `run_lock status` (אם run_lock דלוק).
3. קובץ "הבא בתור" בראש `todo.md`: מזהה הריצה, השעה, והצעד הבא. זו נקודת הכניסה לצ'אט חדש.
4. סוף היומן הכללי; `git log --oneline -15`; `git status --short`.
5. בדיקת חשיפה/משאבים (דיסק, עומס) לפני ריצה כבדה.

## נקודת חזרה (לפני שינוי)
tag `pre-<subject>-s<step>-<yyyymmdd>` + גיבוי לפני שינוי נתונים/תשתית. מיגרציה: `down()` נבדק, או הערה `IRREVERSIBLE: restore from dump`. אסור לעצור בין מיגרציה לקוד שתלוי בה (מסמנים פעולה "ברצף" או "נקודת עצירה בטוחה"). נקודת שחזור לא מחזירה משאבים משותפים ותופעות לוואי: רושמים גבול וניקוי.

## פרוטוקול חזרה (אחרי קטיעה או בצ'אט חדש)
1. בדיקת נעילה; ריצה של מישהו אחר = קריאה בלבד.
2. קריאת קובץ ההתקדמות וסוף יומן הריצה; השוואת טבלת השלבים מול `git log`.
3. המשך מהשלב הראשון שאינו DONE; שלב שיש לו commit אבל מסומן IN PROGRESS רק משלימים את הטבלה. לא חוזרים על DONE.
4. סוכנים שרצו בזמן הקטיעה נעלמו: טיוטה שהשתנתה אחרי הבדיקה האחרונה נבדקת שוב; סוכן חדש מקבל אותו תדריך מקובץ.
5. טבלת "נקטע אחרי פעולה N → מצב חי → ממשיכים מ-...".

## תיעוד תוך כדי ריצה
- שורה ביומן הריצה (`.log`, אנגלית) אחרי כל פעולה ממוספרת, כל `heartbeat_minutes` בפעולה ארוכה, ולפני עצירה: `stopped at action N; live state; next`.
- חותמות זמן רק מ-`date -u`, לא מהזיכרון.
- בקובץ ההתקדמות: ממצאים (מיקום מדויק, מי מצא, חומרה), החלטות וספקות.
- כל פעולה שבוצעה מחוץ לרשימה המאושרת נרשמת מיד כחריגה.

## סיכום סיום (9 שדות, 0-8)
שלב / מה יצא (עם commit) / בדיקות / החלטות וספקות / ממתין לבעלים / נקודת חזרה / איפה מתועד / מה לא נקרא או לא נבדק / שלב הבא מומלץ. ראה `templates/core/he/closing_summary.md`.
בסגירה: בדיקת דיסק, ניקוי משאבים זמניים, ובדיקת סטיית תאריכים/מספרים במסמכים שהריצה נגעה בהם.
