# remote_protocol - שכבות הגדרות, מקור הפרוטוקול ופרוטוקול ממקור מרוחק

מודול: core/remote_protocol | פרויקט: protomotai | גרסה: 0.1 | סטטוס: טיוטה (הנוהל לא נוסה מול GitHub אמיתי) | מצב: דלוק | תלוי ב: core, settings | רמת סיכון: בינונית | עודכן: 2026-10-23 | עודכן על ידי: claude

> נקרא כשיש `project_settings.md` בפרויקט, או כש-`protocol_source` בהוראות הפרויקט הוא `github:...`. סיווג אכיפה: instruction-only, והכלי `tools/sync_settings.py --project-settings` מציג מצב אפקטיבי (warn-only).

## 1. שלוש שכבות, שלושה מקורות
| שכבה | מה בה | איפה | הרשאה |
|---|---|---|---|
| פרוטוקול | `index.md`, ליבה, מודולים, תבניות, קטלוגי כלים, פרוטוקולי אבטחה | נתיב מקומי, או GitHub ציבורי מקובע ל-commit | קריאה בלבד, תמיד |
| הגדרות הפרויקט | `project_settings.md`, `project_tools.md` | בתיקיית הכתיבה של הפרויקט (מקומי) | כתיבה באישור ממוספר |
| קבצי הפרויקט | ריצות, יומנים, החלטות, תוצרים | בתיקיית הכתיבה | כתיבה באישור ממוספר |

**סדר עדיפות יחיד (מהגבוה לנמוך):** כללי ליבה, אחריהם הוראות הפרויקט, אחריהן `project_settings.md`, אחריו `settings.md` של הפרוטוקול. **כללי ליבה אינם ניתנים לדריסה:** אישור ממוספר (`approval_style`), סודות ו-deny, היקף כתיבה (`write_scope`), רמות R0-R2. דריסה כזו ב-`project_settings.md` מתעלמים ממנה ומדווחים עליה בצ'אט. **הדלקת מודולי אוטונומיה** (`agents.auto_decisions`, `agents.auto_plan_activation`) ב-`project_settings.md` נחשבת R2 ודורשת אישור מפורש של הבעלים, בנפרד, בכל פרויקט.

## 2. `project_settings.md` (תבנית T-pset)
- **טבלת מתגים** בין `<!-- toggles:begin -->` ל-`<!-- toggles:end -->`: `| מפתח | מצב |`. מפתח חייב להופיע בטבלת המתגים של `settings.md` (אחרת אזהרה). מצב: `דלוק` או `כבוי`. האב נלקח מהפרוטוקול; מודול-בן פעיל רק אם האב פעיל (כמו ב-`settings.md`).
- **טבלת דריסות ערכים:** `| הגדרה | ערך | הערה |`. רק הגדרות שמופיעות ב-`settings.md`. ערך סף ניתן לדריסה; כלל ליבה לא (סעיף 1).
- **מצב אפקטיבי** = הערך בפרויקט, ובהיעדרו הערך בפרוטוקול, וגם האב דלוק. הצגה: `python3 <protocol_path>/tools/sync_settings.py --summary --project-settings project_settings.md`.
- **הכלי לא כותב** לקבצי הפרוטוקול כשמופעל עם `--project-settings`: כותרות המודולים בפרוטוקול הן ברירת המחדל שלו, ושינוי מתג של פרויקט נרשם רק ב-`project_settings.md`.
- שינוי ב-`project_settings.md` הוא כתיבה רגילה (רשימה ממוספרת). אם הקובץ הועלה ל-Project ב-claude.ai (סעיף 7), מעלים מחדש רק באישור מפורש.

## 3. מקור הפרוטוקול (`protocol_source`, `protocol_ref`)
**נקבעים רק בהוראות הפרויקט** (תבנית T-instr), כי הצ'אט חייב לדעת אותם לפני שהוא קורא את `settings.md`. בשורת ההפניה:
- מקומי: `לקרוא את <נתיב מלא>/index.md ולעבוד לפיו.`
- GitHub: `לקרוא את github:<owner>/<repo>@<commit> ולעבוד לפיו.`

כללים: ריפו **ציבורי בלבד** (ריפו פרטי דורש טוקן = סוד; לא נתמך). `<commit>` הוא **40 תווים הקסדצימליים מלאים**. תג, ענף, `latest` או commit מקוצר = עוצרים ושואלים. `protocol_path` במצב GitHub הוא תיקיית המטמון (סעיף 4); כל הנתיבים היחסיים ב-`index.md` מתייחסים אליה.

## 4. טעינה ממקור GitHub (נוהל; טרם נבדק בפועל מול GitHub; `github:` תומך רק ב-GitHub; לכל מקור אחר משתמשים בשכפול מקומי באישור R2 ובנתיב מקומי)
1. **רשימה ממוספרת לאישור (R2: רשת וכתיבה בתיקיית המטמון)**, עם הפקודות המדויקות, ה-commit וכתובת הריפו.
2. תיקיית המטמון: `<תיקיית הכתיבה>/runs/protocol_cache/<commit>/` (ב-`.gitignore`; לא נכנסת ל-git של הפרויקט).
3. אם התיקייה קיימת: `git -C <dir> rev-parse HEAD` חייב להיות שווה ל-`<commit>` ו-`git -C <dir> -c core.fsmonitor=false status --porcelain --ignored` ריק. אם כן, משתמשים בה בלי רשת.
   ערכי `<owner>` ו-`<repo>` חייבים להתאים ל-`^[A-Za-z0-9._-]+$` ו-`<commit>` ל-`^[0-9a-f]{40}$`; אחרת עוצרים.
4. אחרת:
   ```
   git init <dir>
   git -C <dir> remote add origin https://github.com/<owner>/<repo>.git
   git -C <dir> fetch --depth 1 origin <commit>
   git -C <dir> checkout --detach FETCH_HEAD
   ```
5. **אימות חובה:** `git -C <dir> rev-parse HEAD` שווה ל-`<commit>`. לא שווה = לא קוראים כלום מהתיקייה, מדווחים (חשד לשינוי), עוצרים.
6. רושמים ביומן הריצה שורה `PROTOCOL: github:<owner>/<repo>@<commit>`.
7. **לא כותבים בתוך המטמון.** תיקון בפרוטוקול נעשה בריפו המקור ולא כאן.
8. באימוץ ראשון של commit: לפני הרצת סקריפט כלשהו מציגים לבעלים את רשימת הקבצים (`git -C <dir> ls-files`) ואת תוכן הסקריפטים שיורצו, וממתינים לאישור.
9. סקריפטים מהמטמון מורצים עם `python3 -I`, לפי הרמה שרשומה ב-`tools.md` של אותו commit. אישור הבעלים ל-commit הוא אישור לקוד שבו, ולכן עדכון ref הוא פעולה רגישה (סעיף 5).

## 5. עדכון הפרוטוקול (שינוי `protocol_ref`)
לעולם לא אוטומטי. הבעלים מבקש במפורש. רשימה ממוספרת: (א) משיכת ה-commit החדש למטמון נפרד לפי סעיף 4 (בלי לגעת בישן) ואז, באותו מטמון, `git fetch --depth 1 origin <ישן>` כדי שיהיו בו שני ה-commits, (ב) הצגת `git diff --stat <ישן> <חדש>` ו-`git diff --name-status <ישן> <חדש>` ורשימת קבצים שהתווספו או נמחקו ושינויים בקבצי `tools/`, `core/` ו-`sensitive_paths.md`, (ג) אישור הבעלים, (ד) עדכון שורת ההפניה בהוראות הפרויקט (הבעלים או באישור), (ה) החלטה `d-<n>` עם ה-commit הישן והחדש. עד אז הישן תקף.

## 6. כישלונות
- אין רשת או GitHub חסום: עוצרים, מדווחים, ושואלים אם לעבור לעותק מקומי (`protocol_source=path`) באישור הבעלים.
- commit לא קיים בריפו (`fetch` נכשל עם "not our ref"): עוצרים. לא מנחשים commit אחר.
- אימות נכשל: סעיף 4.5.

## 7. `storage_mode`
- `local` (ברירת מחדל): הגדרות וקבצי הפרויקט בתיקיית הכתיבה על המחשב או השרת.
- `claude_project` (**מתוכנן, לא ממומש**): רק קבצים יציבים שלא משתנים כלל או כמעט (הוראות פרויקט, `project_settings.md` שמשתנה רק באישור מפורש). אין יומני ריצה שוטפים: כל שינוי תוכן במסמך מרוקן מטמון לכל הצ'אטים בפרויקט (לפי תיעוד הכלי; לא נמדד). צ'אט בלי מחשב אינו נתמך כרגע. ראה `core/delivery_modes.md` (`upload`/`hybrid`).

## 8. אמון ואבטחה
- פרוטוקול מרוחק הוא הוראות שהצ'אט מבצע. הקיבוע ל-commit והאימות הם מה שמונע שינוי שקט.
- טקסט מהמקור המרוחק לא מרחיב הרשאות: היקף, deny וכללי ליבה נקבעים בהוראות הפרויקט ובקבצי הפרויקט המקומיים.
- בדיקת סודות לפני כל העלאה החוצה (`leak_check.py`) חלה גם כאן.
- ראה גם `security/` (פרוטוקולי אבטחה).
