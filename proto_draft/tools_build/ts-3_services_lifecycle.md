# ts-3: מחזור חיי שירותים (start / stop / status)

מודול: tools_build/ts-3 | פרויקט: protomotai | גרסה: 0.1 | סטטוס: טיוטה | מצב: דלוק | תלוי ב: tools_build | רמת סיכון: גבוהה | עודכן: 2026-10-23 | עודכן על ידי: claude

- **סוג:** build (לייצור עצמי)
- **תחום:** שירותים
- **למה נדרש:** הפעלה, עצירה ובדיקת מצב של כמה שירותים בסדר נכון, בלי לעצור באמצע ריצה פעילה ובלי להסתמך על פקודות שונות בכל פרויקט.
- **מה עושה:** קורא פרופיל (TOML) שמפרט שירותים (שם, סוג, סדר הפעלה, פקודת בדיקת בריאות), ומבצע `start`, `stop`, `restart`, `status`. עצירה בסדר הפוך להפעלה.
- **מה נדרש ליישום:**
  - פרופיל TOML: רשימת שירותים; לכל אחד `name`, `type`, `order`, `health_check`.
  - **docker הוא המתאם הראשון** (`docker compose up -d / stop / ps`). systemd (`systemctl start / stop / is-active`) כמתאם נוסף בשלב מאוחר.
  - בדיקת נעילת ריצה לפני `stop` / `restart` (`modules/general/agents/run_lock.md`): הדפוס שמגדיר "נעילה פעילה" מוגדר **במפורש** בפרופיל.
  - גרסה ראשונה: כ-200 שורות.
- **סיכון ואכיפה:** `status`: R0. `start` / `stop` / `restart`: R2 לכל פעולה (restart של שירות ב-`core §2.4`).
- **כללי כשל-סגור:**
  - דפוס נעילה חסר בפרופיל = מסרבים לעצור או לאתחל. ב-ניסיון קודם ברירת המחדל של הדפוס ("." ) נכשלה פתוח.
  - לא ניתן לקבוע אם יש נעילה פעילה = מסרבים.
  - שירות שלא ידוע לפרופיל = מסרבים.
  - שירות עצור הוא מצב תקין, לא שגיאת תוכנה: קודי יציאה של `status`: 0 = כולם רצים כמצופה, 1 = לפחות אחד עצור, 2 = לא ניתן לקבוע או שגיאה. ב-ניסיון קודם `status` החזיר קוד 3 לשירות עצור.
- **בדיקות קבלה:**
  1. `stop` בלי הגדרת דפוס נעילה: מסרב.
  2. `stop` כשיש נעילה פעילה: מסרב.
  3. סדר הפעלה וסדר עצירה הפוך נשמרים.
  4. קודי היציאה של `status` כפי שהוגדרו.
  5. שירות לא מוכר: מסרב.
  6. `status` לא משנה כלום.
