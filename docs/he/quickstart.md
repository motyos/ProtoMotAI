מסמך: quickstart | גרסה: 0.1 | סטטוס: טיוטה | עודכן: 2026-10-25 | מתאר פרוטוקול: PROTOMOTAI_V1 (טיוטה)

## מה צריך
- Claude מחובר למחשב או לשרת שלכם, כך שיש לו גישה לתיקיות שבחרתם בלבד. עדיף לחבר רק את התיקיות הנדרשות, ותיקיות לקריאה בלבד כקריאה בלבד.
- תיקיית הפרוטוקול על אותו מחשב, כלומר המאגר הזה. הנתיב המלא אליה נקרא `protocol_path`.
- (מומלץ) git בתיקיית הפרויקט. בלי git יש נוהל חלופי של העתקה לפני שינוי: ראו [שאלות נפוצות](faq.md).

## מונחים שיופיעו בהמשך
- **בדיקת התחלה קרה:** סוכן חדש בלי הקשר קורא רק את נקודת הכניסה ועונה על שאלות. אם לא הצליח, המסמכים חסרים או סותרים.
- **R0 / R1 / R2:** דרגות סיכון. R0 קריאה, R1 כתיבה בהיקף המאושר, R2 פעולה מסוכנת (מחיקה, התקנה, רשת, פרסום) שדורשת אישור נפרד לכל פעולה.
- **takeover:** לקיחת נעילת ריצה תקועה מצ'אט אחר; רק באישור מפורש.
- **deny / mask:** קובץ ב-deny לא נפתח בלי בקשה מפורשת; קובץ ב-mask נקרא רק דרך פקודת מיסוך שמחליפה ערכים רגישים ב-`****` לפני שהפלט מגיע לצ'אט.

## מהו `protocol_path` ואיך מוצאים אותו
זה הנתיב המלא, על המחשב או השרת, לתיקיית הפרוטוקול. אם שכפלתם את המאגר, למשל ל-`/home/me/protomotai`, אז בזמן שהפרוטוקול טיוטה הנתיב הוא `/home/me/protomotai/proto_draft`. בתוך התיקייה הפקודה `pwd` מדפיסה אותו. אחרי שהפרוטוקול יאושר הנתיב יהיה `.../proto_approved`.

## שני דברים שנקראים "הוראות פרויקט"
- **הוראות הפרויקט בצ'אט** (הגדרה ב-claude.ai Project או בפרויקט שלכם): שם נכנסת שורת ההפניה לפרוטוקול. זה מה שאתם כותבים.
- **`instructions/project_instructions.md`**: קובץ שהצ'אט יוצר בתיקיית הכתיבה בצעד הראשון, מתבנית. הוא מכיל את אותה שורת הפניה ואת פרטי הפרויקט, כדי שהמצב יישמר בקובץ.

## פרוטוקול מרוחק (GitHub) והגדרות מקומיות
במקום עותק מקומי אפשר לקרוא את הפרוטוקול ישירות מריפו ציבורי ב-GitHub, **לקריאה בלבד ומקובע ל-commit מלא** (40 תווים, לא תג ולא ענף). בהוראות הפרויקט כותבים: `לקרוא את github:<owner>/<repo>@<commit> ולעבוד לפיו.` Claude מבקש אישור ממוספר, מושך את ה-commit לתיקיית מטמון בתוך תיקיית הכתיבה (`runs/protocol_cache/`), ומוודא שה-commit שנטען שווה לרשום. אם לא, הוא עוצר. ההגדרות והקבצים של הפרויקט (`project_settings.md`, `project_tools.md`, ריצות) נשארים מקומיים. הנוהל עדיין לא נוסה מול GitHub אמיתי. פרטים: `proto_draft/core/remote_protocol.md`.

## איך מדליקים מודול
בקובץ `settings.md` שבתיקיית הפרוטוקול יש טבלת מתגי ברירת מחדל. אם הפרוטוקול מרוחק או שאתם לא רוצים לערוך אותו, רושמים את הדריסות בקובץ `project_settings.md` בתיקיית הכתיבה של הפרויקט (שורה לכל מודול: `| מפתח | מצב |`), ו-`sync_settings.py --summary --project-settings project_settings.md` מציג את המצב האפקטיבי בלי לשנות את הפרוטוקול. אחרת, בטבלת `settings.md` שבעותק המקומי שלכם מחליפים בשורת המודול את `כבוי` ל-`דלוק`, ואומרים לצ'אט "עדכן לפי ההגדרות". הוא מריץ כלי שמעדכן את שורת הכותרת בכל קובץ מודול (אחרי אישור ממוספר). מודול בן פעיל רק אם האב דלוק.

## אפשרות א: פרויקט חדש
פותחים צ'אט חדש עם Claude המחובר, ובהוראות הפרויקט כותבים **שורה אחת**:

```
לקרוא את <protocol_path>/index.md ולעבוד לפיו.
```

(בזמן שהפרוטוקול טיוטה, `<protocol_path>` מצביע על התיקייה `proto_draft`.)

מכאן Claude פותח בארבעה צעדים, ובכל צעד מציג רשימה ממוספרת ומחכה לאישור שלכם:
1. **הוראות הפרויקט** (`instructions/project_instructions.md`): שם הפרויקט, תיקיית כתיבה, תיקיות לקריאה בלבד, גרסת פרוטוקול.
2. **קובץ היקף**: איפה מותר לכתוב, מה מותר רק לקרוא, מה אסור.
3. **רשימת נתיבים רגישים** (`sensitive_paths.md`): קבצי סודות ומה לעשות בכל אחד.
4. **ריצה ראשונה**: קובץ התקדמות ויומן, ומשם עובדים.

מה שלא ברשימת ההיקף אסור גם לקריאה. אם Claude לא יודע משהו, הוא שואל ולא ממציא.

## אפשרות ב: מעבר מפרויקט קיים (מיגרציה)
מדליקים את מודול `migration` (כבוי כברירת מחדל) ואומרים בצ'אט, למשל: "תעבור לעבוד לפי PROTOMOTAI_V1", עם נתיב בשרת או קישור ציבורי של GitHub (מאגר פרטי עדיין לא נתמך).
Claude סורק את הפרויקט **בקריאה בלבד** ולא מריץ בו שום קוד, מפיק דוח פערים מול הפרוטוקול ותוכנית ממוספרת, ורק אחרי האישור שלכם יוצר קבצים. כברירת מחדל הכתיבה היא בענף חדש ובקבצים חדשים בלבד, בלי לשנות קוד קיים.
